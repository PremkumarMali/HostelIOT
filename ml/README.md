# ML: how the AI layer was trained and how well it works

Full numbers: [evaluation_report.md](evaluation_report.md) (regenerated by `python ml/evaluate.py`).

## Run it

```powershell
.\.venv\Scripts\pip install -r ml\requirements.txt
cd ml
..\.venv\Scripts\python download_datasets.py --lbnl   # real data (once)
..\.venv\Scripts\python generate_synthetic.py         # 14 + 7 days of labelled data (~30 s)
..\.venv\Scripts\python train_anomaly.py              # Isolation Forest x3
..\.venv\Scripts\python train_fault_classifier.py     # Random Forest x3
..\.venv\Scripts\python forecast.py                   # self-check of the trend forecast
..\.venv\Scripts\python evaluate.py                   # report (~15 s)
```

Models land in `ml/models/*.joblib` (git-ignored; re-train any time, results are reproducible: fixed seeds).

## Data

| Data | What we use it for |
|---|---|
| **Synthetic** (`generate_synthetic.py`) | Main training set. The *same* sensor models as the live simulator run for 14 days (train) and 7 days (test, different seed); 210 faults are injected at random times on random devices, every row labelled. Leak size varies 0.3x-2x normal flow (drips under 0.8x never wet the floor probe). |
| **UCI Occupancy** (real) | Calibrating realism: our first simulator changed room temperature ~8x faster than real rooms do, so the room physics was slowed down until the minute-to-minute spread matched (0.021 vs 0.033 °C). |
| **NAB machine temperature** (real) | Does Isolation Forest find a real equipment failure it was never told about? |
| **LBNL fan coil unit** (real, labelled) | Does Random Forest name real HVAC faults? Includes "cooling valve stuck open", the real-world twin of our "AC stuck on". |
| ASHRAE GEP III | Not used (Kaggle account needed, see main README). |

## The three layers

1. **Isolation Forest** (`train_anomaly.py`): trained only on normal data, so it needs no fault labels and
   can catch faults nobody planned for. Threshold = 99.9th percentile of normal scores, 2 readings in a row.
2. **Random Forest classifier** (`train_fault_classifier.py`): names the fault (`hvac_stuck_on`, `leak`,
   `compressor_failure`, `door_left_open`). `sensor_offline` has no readings to classify; the heartbeat
   rule (no data for 3 min) catches it.
3. **Trend forecast** (`forecast.py`): straight line through the last 8 readings → "breach in ~N min".

Features (`features.py`, shared with the live engine) use only each device's own past readings: e.g.
`below_setpoint_run` (AC still cooling below its setpoint = relay stuck), `ratio_min_10` (a leak lifts the
lowest flow of the last 10 min), `above_cycle_run` (fridge beyond its normal compressor cycle).

## Results (synthetic test week, 30 devices)

| Fault | Best method | Recall | Precision | False alarms/day | Delay |
|---|---|---|---|---|---|
| AC stuck on in empty room | Random Forest | 1.00 | 1.00 | 0 | 13 min |
| Water leak (incl. drips) | Random Forest | 0.93 | 1.00 | 0 | 1 min |
| Compressor failure | Trend forecast | 0.71 | 1.00 | 0 | 9 min, **8 min before the breach** |
| Door left open | Random Forest | 1.00 | 1.00 | 0 | 4 min |
| Sensor offline | Heartbeat rule | 1.00 | 1.00 | 0 | 3 min |

Real data: Isolation Forest caught **3 of 4** labelled failures in the NAB machine series (0.13 false
alarms/day); Random Forest reached **macro F1 0.83** on 6 real LBNL fan-coil classes (stuck cooling valve:
F1 1.00).

## What we learned (worth saying in the viva)

- **Label the invisible part honestly.** The first minutes of a fault look exactly like normal operation
  (a door open 2 min is normal; setback only starts after 10 vacant minutes). Training on those minutes
  taught the classifier to flag normal behaviour: 11 false alarms/day. Skipping them: 0.
- **Physics beats generic features.** Adding one feature, "still cooling below setpoint", made the AC-fault
  classifier perfect.
- **Isolation Forest is a safety net, not the main signal.** It finds every AC fault but also flags rare
  normal situations (5.7 false alarms/day on rooms), so the AI engine uses it to raise *warnings* and lets
  the classifier name the fault.
- **Forecasts must ignore normal cycles.** Without the "outer 20 % of the band, rising 4 readings, door
  closed" guard, the trend forecast raised 145 false alarms a day.
- **Limits:** synthetic faults are cleaner than real ones; 2 of 7 compressor failures ended before the
  forecast could fire; small drips are the hardest leaks. Real hotel data (ESP32 sensors) is the next step.
